# Local MVP verification — 2026-10-04

Scope: development tasks 2–3, covering working MVP journeys, responsive layouts, keyboard operation, and failure states. This is local Chromium evidence, not deployment verification or a complete accessibility certification.

## Changes verified

- Fixed entry dialogs closing immediately during React Strict Mode effect cleanup. The queued close event is ignored when the dialog has already reopened.
- Added explicit initial focus, Tab containment, Escape handling, and restoration to the dialog trigger.
- Added category filtering alongside type filtering and trimmed, case-insensitive search. An unmatched search now offers a clear-filter action.
- Returned save errors to the open transaction/budget form. Failed mutations retain saved data and visible state; delete/reset failures use error feedback rather than success styling.
- Added visible reset failure feedback on the recovery screen and a non-destructive retry after storage permissions are restored.
- Made the closed phone menu inert, contained keyboard focus while it is open, and restored focus to its trigger when closed.
- Changed phone transaction rows into cards with wrapping titles and larger action buttons; stacked form fields; improved primary text contrast and focus indicators; respected reduced-motion preferences.

## Failure investigation

- The first baseline run had two startup timeouts before reaching CRUD. Trace data showed slow Vite/dependency responses. The suite now uses one worker on this memory-constrained machine, a 60-second per-test budget and a 10-second action timeout. Navigation waits for the DOM and assertions then wait for the intended UI; retries remain disabled.
- Subsequent runs reproduced the actual Strict Mode dialog defect, the missing category filter and missing recovery error feedback.
- New exact-label selectors included option text when matching a wrapping label. Those test selectors were corrected to use the dropdown's actual accessible role/name. Currency assertions accept the optional spacing produced by browser `Intl` implementations while retaining exact amounts.
- A keyboard regression exposed inconsistent initial focus; explicit dialog focus handling fixed it.
- Computed primary-text contrast checks identified pale landing/navigation copy, which was darkened while keeping the existing palette.
